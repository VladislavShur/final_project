## Bug Report #1: תלות בנתיב קשיח מוחלט (Hardcoded Path Dependency)
* **מזהה באג:** BUG-001
* **רכיב:** `task01.py`, `tast02.py`
* **רמת חומרה (Severity):** **High**
* **סטטוס:** **Closed / Resolved & Verified**
* **תיאור:**
  הקוד השתמש בנתיב מוחלט של מערכת הפעלה Windows (`path = "C:\\Users\\Admin\\tasks.csv"`). בעת הרצה בסביבות Linux או macOS, פייתון זרק מיידית שגיאת `FileNotFoundError` או שגיאת נתיב לא חוקי.
* **שלבי שחזור:**
  1. העבר את הקוד למחשב מבוסס Mac / Linux.
  2. הרץ את הקובץ: `python3 Final-project/task01.py` ובחר `1`.
  3. תוצאה בפועל: קריסה או הודעת כשל בקריאת הקובץ.
* **התיקון שבוצע:**
  הסרת כל הנתיבים הקשיחים והמרתם לשימוש ב-`pathlib.Path` יחסי למיקום הקובץ:
  ```python
  from pathlib import Path
  BASE_DIR = Path(__file__).resolve().parent
  DATA_PATH = BASE_DIR / "tasks.csv"
  ```

## Bug Report #2: צבירת כפילויות בזיכרון בקריאה חוזרת (Data Accumulation Bug)
* **מזהה באג:** BUG-002
* **רכיב:** `task01.py`
* **רמת חומרה (Severity):** **Medium**
* **סטטוס:** **Closed / Resolved & Verified**
* **תיאור:**
  הפונקציה שטוענת את המשימות ביצעה הוספה ישירה למשתנה הגלובלי `tasks.append(...)` ללא איפוס מקדים. כתוצאה מכך, בכל פעם שהמשתמש בחר באופציה `1` (הצגת משימות), כל המשימות שוב שוכפלו בזיכרון ונשמרו כפולות לקובץ בסיום.
* **שלבי שחזור:**
  1. הכנס משימה אחת לקובץ ה-CSV.
  2. הפעל את הסקריפט ובחר באופציה `1` פעמיים ברציפות.
  3. בחר באופציה `4` לשמירה ויציאה ובדוק את הקובץ.
  4. תוצאה בפועל: הקובץ מכיל 2 שורות במקום 1.
* **התיקון שבוצע:**
  איפוס המערך הגלובלי לפני טעינת הרשומות מחדש:
  ```python
  def load_tasks() -> bool:
      global tasks
      ...
      tasks = loaded  # השמה ישירה שמאפסת את הזיכרון הקודם
  ```

## Bug Report #3: היעדר בדיקת זמינות לפני השאלת ציוד (Business Logic Gap)
* **מזהה באג:** BUG-003
* **רכיב:** `asset_tracker.py`
* **רמת חומרה (Severity):** **Medium**
* **סטטוס:** **Closed / Resolved & Verified**
* **תיאור:**
  בלוגיקה המקורית, הסקריפט קיבל שם נכס ועובד ומייד הוסיף שורה חדשה לקובץ, מבלי לבדוק האם הנכס כבר קיים והאם הוא כבר מושאל לעובד אחר (`status == "ASSIGNED"`). הדבר גרם לכפילות שיוך של אותו מחשב לשני עובדים שונים.
* **שלבי שחזור:**
  1. בחר באפשרות השאלת ציוד והשאל את `Laptop A` ל-`Alice`.
  2. בחר שוב בהשאלת ציוד והשאל את אותו `Laptop A` ל-`Bob`.
  3. תוצאה בפועל: שני עובדים רשומים במקביל על אותו מחשב.
* **התיקון שבוצע:**
  הוספת בדיקת ולידציה עסקית מקדימה:
  ```python
  if item.get("status", "").upper() == "ASSIGNED":
      return False, f"Error: Asset '{asset_name}' is already ASSIGNED to {current_owner}!"
  ```

## Bug Report #4: דריסת נתונים היסטוריים בעת הוספה (Data Overwrite Risk)
* **מזהה באג:** BUG-004
* **רכיב:** `asset_tracker.py`
* **רמת חומרה (Severity):** **High**
* **סטטוס:** **Closed / Resolved & Verified**
* **תיאור:**
  פתיחת הקובץ במצב כתיבה מלאה (`"w"`) מבלי לוודא שטוענים קודם לכן את כל הנתונים ההיסטוריים גרמה לכך שהקובץ התאפס והכיל רק את השורה החדשה שהתווספה.
* **שלבי שחזור:**
  1. פתח סקריפט עם קובץ המכיל נכסים קיימים מבלי להציגם קודם לכן.
  2. הוסף פריט חדש ושמור.
  3. תוצאה בפועל: כל הפריטים הקודמים נמחקו מהקובץ.
* **התיקון שבוצע:**
  כל פעולת כתיבה מחייבת טעינה אטומית מקדימה של כל הרשומות הקיימות בקובץ, עדכון הרשימה בזיכרון, ושמירה מסודרת.

## Bug Report #5: קריסה בחלוקה באפס ובקלט עברי (ZeroDivision & Type Casting)
* **מזהה באג:** BUG-005
* **רכיב:** `analyzer_service.py`, `log_storage.py`
* **רמת חומרה (Severity):** **Medium**
* **סטטוס:** **Closed / Resolved & Verified**
* **תיאור:**
  1. קובץ ריק או קובץ שבו כל זמני הריצה הם 0 גרם ל-`ZeroDivisionError` בחישוב ממוצע זמנים.
  2. טקסט עברי בעמודות מספריות גרר `ValueError` בהמרה ל-`float`.
* **התיקון שבוצע:**
  1. הוספת תנאי מגן: `avg_dur = sum(durations) / len(durations) if durations else 0.0`.
  2. המרה מוגנת עם `try-except ValueError` וברירת מחדל של `0.0`.
