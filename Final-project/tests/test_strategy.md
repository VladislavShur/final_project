# אסטרטגיית בדיקות וניהול סיכונים (Test Strategy & Risk Analysis)

## 1. היקף הבדיקות (Scope)
מסמך זה מגדיר את אסטרטגיית הבדיקות של כלי ה-CLI בפרויקט, תוך התמקדות ב:
* **בדיקות פונקציונליות (Functional Testing):** אימות כלל היכולות העסקיות לפי מסמך הדרישות.
* **בדיקות אינטגרציה וקבצים (File I/O Integration):** קריאה וכתיבה של קובצי נתונים (`CSV`, `TXT`).
* **בדיקות עמידות ומקרי קצה (Edge Cases & Robustness):** טיפול בקבצים ריקים, חסרי הרשאות, תווים בעברית בשדות מספריים, וקלט שגוי מהמשתמש.
* **בדיקות רגרסיה ואימות תיקון באגים (Bug Verification):** וידוא חסימת כפילויות, מניעת דריסת נתונים והסרת נתיבים קשיחים.

---

## 2. סביבת הבדיקות (Test Environment)
* **מערכות הפעלה נתמכות:** macOS, Linux, Windows.
* **סביבת ריצה:** Python 3.10 ומעלה (נבדק על Python 3.13).
* **כלי הרצה:** `unittest`, סקריפטי CLI ייעודיים, בדיקות טרמינל ישירות.

---

## 3. רמות הבדיקה (Test Levels)
1. **בדיקות יחידה ואינטגרציה (Unit & Integration Tests):**
   * בדיקת פונקציות הליבה של השירותים (`TaskService`, `LogAnalyzerService`, `AssetTracker`).
   * בידוד סביבת הבדיקה באמצעות קבצים זמניים (`setUp` ו-`tearDown`).
2. **בדיקות מערכת וממשק טרמינל (System & CLI Testing):**
   * סימולציית תפריט אינטראקטיבי, תגובות לבחירה לא חוקית, קליטת שדות ריקים.
3. **בדיקות קצה ושליליות (Negative & Edge Case Testing):**
   * שימוש בחבילת קבצי קצה מנוהלת תחת `Final-project/edge_case_inputs/`.

---

## 4. ניתוח סיכונים ותוכנית הפחתה (Risk Analysis & Mitigation)

| סיכון מזוהה | רמת חומרה | השפעה פוטנציאלית | מנגנון הפחתה שנבדק ואומת |
| :--- | :---: | :--- | :--- |
| **תלות בסביבת הפעלה (Hardcoded Paths)** | **High** | קריסה מיידית בסביבות שאינן Windows. | מעבר ל-`pathlib.Path` יחסי עם `BASE_DIR = Path(__file__).resolve().parent`. |
| **אובדן / דריסת נתונים (Data Overwrite)** | **High** | פתיחת קובץ ב-`"w"` לפני טעינת היסטוריה דורסת נתונים קודמים. | טעינה מוקדמת מלאה של הקובץ לפני כתיבה מחודשת, או עבודה ב-Append. |
| **כפילויות זיכרון (Memory Accumulation)** | **Medium** | טעינה חוזרת מכפילה שורות בקובץ ובזיכרון. | איפוס המערך הגלובלי לפני כל פעולת השמה וטעינה. |
| **חריגת גבולות אינדקס (IndexError)** | **Medium** | הזנת אינדקס שגוי או אותיות בתפריט עדכון משימה מפילה את הסקריפט. | בדיקות `isdigit()` ובדיקת טווח קפדנית `0 <= idx < len(items)`. |
| **טיפוסי נתונים שגויים (Type Coercion)** | **Medium** | עברית או סימנים מיוחדים בעמודת זמנים (`duration`) גוררים `ValueError`. | מנגנון המרה מוגן עם ערך ברירת מחדל של `0.0`. |
| **חלוקה באפס (ZeroDivisionError)** | **Medium** | קובץ ריק או קובץ עם זמנים של 0 שניות גורר קריסה בחישוב ממוצעים. | בדיקות מפורשות: `sum(durations) / len(durations) if durations else 0.0`. |
| **שיבושי קידוד (Unicode Errors)** | **Medium** | קריסה או שיבוש תווים עבריים בעת כתיבה/קריאה. | אכיפת `encoding="utf-8"` בכל פתיחת קובץ. |

## 5. קריטריוני קבלה לשחרור (Release Criteria)
* **100% מעבר** של כל בדיקות ה-STD האוטומטיות ללא נפילות.
* **0 שגיאות קריסה** במערך בדיקות מקרי הקצה (`edge_case_inputs`).
* עמידה מלאה בכללי העבודה הבטוחה עם קבצים ([GEMINI.md](../../GEMINI.md)).
